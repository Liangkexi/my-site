# 信息系统架构

## 考情分析
- 本章为信息系统架构核心章节，分值占比约4～6分
- 常见题型：选择题为主，可能涉及简答
- **高频考点**：总体框架四层次、物理架构与逻辑架构、常用架构模型（C/S、B/S、SOA）、TOGAF-ADM阶段、应用架构原则、数据架构原则、网络架构原则

## 核心考点

### 一、架构基础（4.1）

**架构的本质**：决策——在权衡方向、结构、关系及原则各方面因素后进行的决策。

**信息系统体系架构总体框架四部分**：

| 层次 | 对应管理 | 组成部分 | 核心作用 |
|------|------|------|------|
| 第一层 | 战略管理 | **战略系统** | 高层决策支持；战略规划体系 |
| 第二层 | 战术管理 | **业务系统** + **应用系统** | 业务建模优化；信息处理实现 |
| 第三层 | 运行管理 | **信息基础设施** | 计算、传输、数据等基础支持 |

**信息基础设施**又分为三部分：
- **技术基础设施**：计算机设备、网络、系统软件
- **信息资源设施**：数据与信息本身、交换标准、处理方法
- **管理基础设施**：组织架构、人员分工、管理规章制度

其中信息资源设施相对变化较小，技术基础设施和管理基础设施变化较多。

### 二、系统架构（4.2）

#### （1）架构分类

**物理架构**两大类：
- **集中式架构**：资源空间集中，便于管理但脆弱性强，单一故障点
- **分布式架构**：通过网络连接各地资源，应变能力强，安全性好，但管理协调困难。分为一般分布式与客户端/服务器模式。

**系统融合三种方式**：
- **横向融合**：同一层次各职能融合在一起
- **纵向融合**：某职能各层次业务组织在一起（上下贯通）
- **纵横融合**：信息模型和处理模型两方面综合，建立公用数据体系

#### （2）信息系统架构基本原理

架构包含两个基本部分：**组成分**和**组成分之间的关系**。析出相对稳定的部分，在稳定部分支持下对变化部分重新组织，使信息系统对环境变化具有适应能力（柔性）。

#### （3）常用架构模型

| 架构模型 | 特点 |
|------|------|
| **单机应用模式** | 运行在一台物理机器上，独立的应用程序 |
| **两层C/S** | "胖客户端"模式：前台界面+后台数据库 |
| **三层C/S与B/S** | 前台+Web服务器+数据库；B/S是采用通用客户端界面的三层C/S |
| **多层C/S** | 四层：浏览器+Web服务器+中间件/应用服务器+数据库服务器 |
| **MVC模式** | Model（模型）+View（视图）+Controller（控制器） |
| **SOA模式** | 面向服务架构，独立应用间通过消息通信 |
| **组织级数据交换总线** | 不同应用间信息交换的公共通道（连接器） |

**B/S（浏览器/服务器）**是三层C/S的一种典型实现。SOA的本质是消息机制或远程过程调用（RPC）。

#### （4）集成架构演进（以工业企业为例）

| 阶段 | 架构主线 | 特征 |
|------|------|------|
| 初级 | **以应用功能为主线** | 采购成熟软件，按需部署，关注软件功能 |
| 中级 | **以平台能力为主线** | 平层化建设，平台化+快速定制，双态IT |
| 高级 | **以互联网为主线** | API化/微服务，通过API编排适配不同成熟度 |

#### （5）TOGAF架构开发方法（ADM）

ADM全生命周期10个阶段：预备阶段 → A.架构愿景 → B.业务架构 → C.信息系统架构 → D.技术架构 → E.机会和解决方案 → F.迁移规划 → G.实施治理 → H.架构变更治理，全程伴随**需求管理**。

TOGAF核心思想：模块化架构、内容框架、扩展指南、架构风格。

### 三、应用架构（4.3）

**应用架构五项原则**：

| 原则 | 核心要点 |
|------|------|
| **业务适配性** | 支撑业务战略目标，具备灵活性和可扩展性 |
| **应用聚合化** | 整合部门级应用，推动组织级应用系统 |
| **功能专业化** | 按业务功能聚合进行规划，实现专业化 |
| **风险最小化** | 降低耦合度，松耦合，规避单点风险 |
| **资产复用化** | 提炼重用架构资产，快速开发降低成本 |

应用架构采用分层分组策略：分层实现业务与技术分离，降低耦合；分组体现功能分类聚合，高内聚低耦合。

### 四、数据架构（4.4）

**数据架构演进三阶段**：单体应用架构时代 → 数据仓库时代 → 大数据时代。

**数据架构五项原则**：
- **数据分层原则**：按生命周期分层定位
- **数据处理效率原则**：追求合理效率而非最高，减少冗余存储和大规模搬迁
- **数据一致性原则**：减少重复加工和冗余存储
- **可扩展性原则**：清晰分层定位+合适的模型和存储技术
- **服务于业务原则**：业务体验可优先于其他原则

### 五、技术架构（4.5）

**技术架构五项原则**：

| 原则 | 核心要点 |
|------|------|
| **成熟度控制** | 优先使用成熟度高且在活跃期的技术 |
| **技术一致性** | 减少技术异构，统一技术版本 |
| **局部可替换** | 标记需关注的技术，明确替代方案 |
| **人才技能覆盖** | 技术人员能驾驭所选技术 |
| **创新驱动** | 挖掘技术对业务发展的引领作用 |

### 六、网络架构（4.6）

**网络架构五项原则**：高可靠性、高安全性、高性能、可管理性、平台化和架构化。

**局域网单核心架构特点**：
- 核心交换设备采用二层/三层及以上交换机，可划分VLAN
- 接入交换设备采用二层交换机
- VLAN内二层转发，VLAN间三层路由
- 连接采用10M/GE/10GE以太网

## 记忆要点
- **总体框架四层**：战略系统→业务系统+应用系统→信息基础设施
- **物理架构两类**：集中式vs分布式
- **融合方式三种**：横向融合、纵向融合、纵横融合
- **C/S演进路线**：两层C/S→三层C/S(B/S)→多层C/S→MVC→SOA
- **工业集成架构演进**：功能主线→平台主线→互联网主线
- **ADM十阶段**：预备→愿景→业务→信息系统→技术→机会→迁移→实施→变更治理+全程需求管理
- **应用架构五原则**：适配、聚合、专业、风险最小、复用

## 常见题型
1. **选择题**：信息系统总体框架中属于战术管理层的部分（业务系统+应用系统）
2. **选择题**：B/S属于哪种架构模式（采用通用客户端界面的三层C/S结构）
3. **选择题**：TOGAF架构开发方法的核心是什么（ADM）
4. **选择题**：物理架构中集中式的缺点（资源过于集中造成系统脆弱）
5. **简答题**：简述应用架构设计的基本原则（业务适配性、应用聚合化、功能专业化、风险最小化、资产复用化）
