# 信息安全工程

## 考情分析
- 本章属于信息技术基础章节，分值占比约2～3分
- 常见题型：选择题为主
- **高频考点**：信息安全三维空间与五大属性、安全机制（WPDRC体系）、安全服务（7种）、CIA三要素、信息系统安全等级保护（5级）、ISO/IEC 270系列标准、ISE-CM三大过程

## 核心考点

### 一、信息安全基础（8.1）

**信息安全概念**：伴生于信息系统而存在。信息安全强调保护信息的**保密性（Confidentiality）、完整性（Integrity）和可用性（Availability）**，即**CIA三要素**。

**信息安全管理体系**：
- 国际标准：ISO/IEC 270系列标准，从**组织、人员、物理、技术**4个方面给出控制
- 国家标准：GB/T 20269（信息系统安全管理要求）
- 等级保护：《信息安全等级保护管理办法》将信息系统安全保护等级分为**5级**

> 记忆技巧：CIA三要素 = 保密性（不泄露）+ 完整性（不被篡改）+ 可用性（能访问）

**信息系统安全保护等级（等保2.0）**：
| 等级 | 保护对象 | 侵害后果 |
|------|---------|---------|
| 第1级 | 一般信息系统 | 损害公民、法人合法权益 |
| 第2级 | 一般信息系统 | 严重损害或损害社会秩序/公共利益 |
| 第3级 | 重要信息系统 | 特别严重损害社会秩序/公共利益 |
| 第4级 | 重要信息系统 | 特别严重损害国家安全 |
| 第5级 | 极端重要信息系统 | 特别严重损害国家安全 |

**信息安全管理5个基本原则**：需要与业务紧密结合、需要上层领导的重视与支持、需要全体员工的参与、需要明确的责任分工、需要持续改进。

### 二、信息安全体系架构（8.2）

信息安全系统的三维架构由X轴（安全机制）、Y轴（OSI网络参考模型）、Z轴（安全服务）组成，形成"**安全空间**"。安全空间具有**认证、权限、完整、加密和不可否认五大属性**。

#### 2.1 安全机制（X轴，共9类）

| 安全机制 | 主要内容 |
|---------|---------|
| **基础设施安全** | 机房安全、场地安全、设施安全、动力系统安全、灾难预防与恢复 |
| **平台安全** | OS漏洞检测与修复、网络漏洞检测与修复、通用应用漏洞检测、网络安全产品部署 |
| **数据安全** | 介质保护、数据访问控制、数据完整性、数据可用性、数据监控审计、存储备份安全 |
| **通信安全** | 通信线路安全测试、网络加密设施、身份鉴别机制、安全通道设置、网络协议漏洞测试 |
| **应用安全** | 业务软件程序安全测试（Bug）、防抵赖测试、访问控制验证、身份鉴别、备份与恢复 |
| **运行安全** | 应急处置机制、网络安全监测、安全产品运行监测、定期检查评估、系统升级补丁 |
| **管理安全** | 人员管理、培训管理、应用系统管理、软件管理、设备管理、文档管理、数据管理 |
| **授权和审计安全** | 权限管理、授权服务、用户身份到应用授权的映射、与具体应用无关的访问控制机制 |
| **安全防范体系（WPDRC）** | 预警（Warn）、保护（Protect）、检测（Detect）、反应（Response）、恢复（Recover）、反击（Counter-attack） |

> WPDRC构成综合信息安全保障体系，可从**人员、技术、政策**三大要素构建。

#### 2.2 安全服务（Z轴，共7种）

| 安全服务 | 功能描述 |
|---------|---------|
| **对等实体认证服务** | 确认通信对方实体的合法性、真实性，防止假冒 |
| **访问控制服务** | 保护信息免于被未经授权实体访问，分自主访问控制、强制访问控制、基于角色访问控制 |
| **数据保密服务** | 防止数据被截获或非法存取，提供密码加密保护；支持链接/无链接方式 |
| **数据完整性服务** | 防止非法实体对数据的修改、插入、删除及交换中的数据丢失（5种子类型） |
| **数据源点认证服务** | 确保数据发自真正的源点，防止假冒 |
| **禁止否认服务** | 防止发送方否认发送、接收方否认接收（不得否认发送 + 不得否认接收） |
| **犯罪证据提供服务** | 为违反法律法规的行为提供数字证据、信息线索 |

### 三、工程体系架构（8.3）

#### 3.1 基本概念

**信息安全系统工程（ISE）**：确定系统和过程的安全风险，使安全风险降到最低或得到有效控制。

**关键区分**：
- **业务应用信息系统工程**：关注客户需求、业务流程、价值链优化
- **信息安全系统工程**：关注安全风险评估、安全策略、安全需求、安全系统设计等

两者密不可分，但功能、操作流程、管理方式、人员要求、技术领域完全不同。

ISE活动离不开相关工程：硬件工程、软件工程、通信及网络工程、数据存储与灾备工程、系统工程、测试工程、密码工程、组织信息化工程。

#### 3.2 ISE-CM（信息安全系统工程能力成熟度模型）

ISE-CM是衡量信息安全系统工程实施能力的度量标准，建立在**统计过程控制理论**基础上。覆盖：
- 全生命期（开发、运行、维护、终止）
- 管理、组织和工程活动
- 与其他规范（系统、软件、硬件、测试等）的并行交互
- 与其他组织（获取、认证、认可、评估组织）的交互

**适用三类组织**：工程组织（系统集成商/应用开发商）、获取组织（采购方）、评估组织（认证/授权组织）。

#### 3.3 ISE三大过程

ISE实施过程分解为三个基本组成部分：

| 过程 | 功能 | 核心活动 |
|------|------|---------|
| **工程过程** | 实施安全解决方案 | 确定安全需求→提供安全输入→实施安全控制→监控安全态势→协调安全 |
| **风险过程** | 识别和降低风险 | 评估威胁→评估脆弱性→评估影响→评估安全风险（有害事件 = 威胁 + 脆弱性 + 影响） |
| **保证过程** | 建立安全可信度 | 验证和证实安全→建立保证论据（正确性：按设计实现需求；有效性：满足用户安全需求） |

> 三道过程相互独立但又有机联系。安全保证不增加抵抗能力，但为减少预期安全风险提供信心。

#### 3.4 ISE-CM体系结构（两维模型）

**域维（安全工程过程域）**：共22个过程域（PA01～PA22），包括11个安全工程过程域和11个项目/组织过程域。
- 安全工程过程域：PA01实施安全控制、PA02评估影响、PA03评估安全风险、PA04评估威胁、PA05评估脆弱性、PA06建立保证论据、PA07协调安全、PA08监控安全态势、PA09提供安全输入、PA10确定安全需求、PA11验证和证实安全
- 项目组织过程域：PA12保证质量、PA13管理配置至PA22与供应商协调

**能力维（公共特性）**：5个等级，从低级到高级依次增强组织能力：

| 级别 | 名称 | 重点 | 能力特点 |
|------|------|------|---------|
| **1级** | 非正规实施级 | 执行基本实施 | 必须先做，才能管理 |
| **2级** | 规划与跟踪级 | 项目层面的定义、规划和执行 | 定义组织层面过程前，先弄清项目事项 |
| **3级** | 充分定义级 | 规范化裁剪组织层面的过程定义 | 用项目中学到的最好东西定义组织过程 |
| **4级** | 量化控制级 | 测量与业务目标关联 | 只有知道它是什么，才能测量；测量正确对象时管理才有意义 |
| **5级** | 持续改进级 | 通过文化转变持续改进 | 需要完备的管理实施、已定义的过程和可测量的目标 |

**5级核心逻辑链**：先做 → 管项目事 → 定义组织标准 → 量化测量 → 持续改进文化

## 记忆要点
- **CIA三要素**：保密性、完整性、可用性
- **安全空间五大属性**：认证、权限、完整、加密、不可否认
- **安全机制9类速记**：基平数通应运管授防（基础/平台/数据/通信/应用/运行/管理/授权审计/防范WPDRC）
- **WPDRC**：预警（Warn）、保护（Protect）、检测（Detect）、反应（Response）、恢复（Recover）、反击（Counter-attack）
- **安全服务7种**：认证、访问控制、保密、完整性、源点认证、禁止否认、犯罪证据
- **ISE三大过程**：工程过程（做）→ 风险过程（管风险）→ 保证过程（建信心）
- **ISE-CM 5级模型**：非正规→规划跟踪→充分定义→量化控制→持续改进
- **等保5级**：公民→社会→特别严重社会→国家安全→特别严重国家安全
- **ISO/IEC 270系列控制**：组织、人员、物理、技术

## 常见题型
1. **选择题**：不属于CIA三要素的是（如"可靠性"不属CIA，CIA为保密性/完整性/可用性）
2. **选择题**：ISO/IEC 270系列标准的控制方面（组织、人员、物理、技术）
3. **选择题**：信息系统安全保护等级划分的级别数（5级）
4. **选择题**：不属于基础设施实体安全的是（数据安全属于数据安全机制）
5. **选择题**：ISE实施过程的三个组成部分（工程过程、风险过程、保证过程）
