# 监控过程组

## 考情分析
- 本章是**项目管理十大知识领域中监控过程组的全部内容**，是考试**最核心章节之一**
- 选择题高频考点：控制质量工具（因果图、控制图、直方图、散点图）、**挣值分析（EVA）**公式计算、变更控制流程、工作绩效数据/信息/报告的区别
- 简答题高频考点：挣值分析计算题（PV、EV、AC、SV、CV、SPI、CPI、EAC），整体变更控制流程
- 案例分析常考：根据挣值数据判断项目状态（进度超前/落后、成本节约/超支），提出纠正措施
- 预计分值：选择题5~8分，案例题可能单独出计算题（5~10分）

## 核心考点

### 13.1 控制质量
- **控制质量**是监控和记录质量管理活动执行结果，评估绩效，确保项目输出完整、正确并满足客户期望的过程
- 主要输入：项目管理计划（质量管理计划）、项目文件（经验教训登记册、质量测量指标、测试与评估文件）、**批准的变更请求**、可交付成果、工作绩效数据
- 主要工具与技术：
  - **核对单**：以结构化方式管理控制质量活动
  - **核查表（计数表）**：用于收集属性数据，如缺陷数量
  - **统计抽样**：从目标总体中选取部分样本检查
  - **问卷调查**：收集客户满意度数据
  - **绩效审查**：比较质量测量指标的实际与计划
  - **根本原因分析（RCA）**：识别缺陷成因
  - **检查**：检验工作产品是否符合书面标准（又称审查、同行审查、审计、巡检）
  - **测试/产品评估**：找出产品或服务的错误、缺陷、漏洞
  - 数据表现：**因果图**（识别质量缺陷和错误原因）、**控制图**（确定过程是否稳定）、**直方图**（按来源展示缺陷数量）、**散点图**（计划vs实际绩效）
- 主要输出：**质量控制测量结果**、**核实的可交付成果**（作为确认范围过程的输入）、工作绩效信息
- 控制质量与确认范围的区别：前者关注可交付成果的**正确性**，后者关注可交付成果的**验收**

### 13.2 确认范围
- **确认范围**是正式验收已完成的项目可交付成果的过程
- 主要作用：使验收过程具有客观性；提高最终产品获得验收的可能性
- 确认范围的步骤：①确定范围确认时间；②识别范围确认所需投入；③确定范围正式被接受的标准和要素；④确定范围确认会议的组织步骤；⑤组织范围确认会议
- **确认范围前，项目团队需要先进行质量控制工作**
- 确认范围时需检查的6个问题：可交付成果是否确定可确认；是否有明确里程碑；是否有明确质量标准；审核和承诺是否清晰；范围是否覆盖所有活动；风险是否过高
- 干系人关注点：管理层关注项目范围对进度资金资源的影响；客户关注产品范围；项目管理人员关注制约因素；团队成员关注自己参与的元素
- 主要输入：范围管理计划、需求管理计划、范围基准、**核实的可交付成果**
- 主要输出：**验收的可交付成果**（由客户或发起人正式签字批准）、工作绩效信息

### 13.3 控制范围
- **控制范围**是监督项目和产品的范围状态，管理范围基准变更的过程
- 主要作用：在整个项目期间保持对范围基准的维护
- **范围蔓延**：未经控制的产品或项目范围的扩大（未对时间、成本和资源做相应调整）
- 主要输入：范围管理计划、需求管理计划、变更管理计划、配置管理计划、**范围基准**、绩效测量基准
- 工具与技术：**偏差分析**、**趋势分析**
- 主要输出：工作绩效信息（包括收到的变更分类、范围偏差及原因、对进度成本的影响、将来范围绩效预测）

### 13.4 控制进度
- **控制进度**是监督项目状态以更新项目进度和管理进度基准变更的过程
- 关注内容：判断项目进度当前状态；对引起进度变更的因素施加影响；重新考虑必要的进度储备；判断进度是否已经发生变更；在变更实际发生时对其进行管理
- 敏捷方法控制进度关注：比较已交付验收工作量与估算值；实施回顾性审查；对剩余工作重新排序；确定每次迭代可交付成果的速度；确定进度变更
- 工具与技术：
  - **挣值分析**：SV、SPI
  - **迭代燃尽图**：追踪迭代未完项中尚待完成的工作
  - **绩效审查**：对比实际开始/完成日期、已完成百分比
  - **趋势分析**：检查项目绩效随时间变化
  - **偏差分析**：关注实际与计划的偏离
  - **假设情景分析**：评估各种不同情景
  - **关键路径法**：检查关键路径的进展
  - **资源优化**、**提前量和滞后量**、**进度压缩**（快速跟进、赶工）
- 主要输出：工作绩效信息、**进度预测**

### 13.5 控制成本（挣值管理核心）
- **控制成本**是监督项目状态以更新项目成本和管理成本基准变更的过程
- 成本控制目标：对造成成本基准变更的因素施加影响；确保变更请求得到及时处理；确保成本支出不超过批准的资金限额；监督成本绩效；防止未经批准的变更；设法把预期成本超支控制在可接受范围内

#### 挣值分析（EVA）核心公式（必背！）
- **PV（计划值）**：计划完成工作的预算费用。总PV = BAC（完工预算）
- **AC（实际成本）**：实际完成工作所消耗的费用
- **EV（挣值）**：实际完成工作量按预算定额计算的费用
- **SV = EV - PV**：进度偏差。SV > 0 进度超前；SV < 0 进度落后
- **CV = EV - AC**：成本偏差。CV > 0 成本节省；CV < 0 成本超支
- **SPI = EV / PV**：进度绩效指数。SPI > 1 进度超前；SPI < 1 进度落后
- **CPI = EV / AC**：成本绩效指数。CPI > 1 成本节省；CPI < 1 成本超支
- **EAC = AC + ETC**：完工估算
  - 非典型偏差：ETC = BAC - EV
  - 典型偏差：ETC = (BAC - EV) / CPI 或 EAC = BAC / CPI
- **TCPI（完工尚需绩效指数）**：
  - 基于BAC：TCPI = (BAC - EV) / (BAC - AC)
  - 基于EAC：TCPI = (BAC - EV) / (EAC - AC)

- 其他工具与技术：**偏差分析**（无挣值管理的项目）、**趋势分析**、**储备分析**（监督应急储备和管理储备使用情况）

### 13.6 控制资源
- **控制资源**是确保按计划为项目分配实物资源，监督资源实际使用情况的过程
- 重点关注**实物资源**（设备、材料、设施和基础设施），不包括人力资源
- 关注：监督资源支出；及时识别资源缺乏/剩余；确保资源使用符合计划；出现资源问题时通知干系人；影响导致资源使用变更的因素
- 主要输入：资源管理计划、问题日志、物质资源分配单、项目进度计划、资源分解结构、资源需求、风险登记册、**协议**
- 工具与技术：备选方案分析、成本效益分析、绩效审查、趋势分析、**问题解决**、谈判、影响力

### 13.7 监督沟通
- **监督沟通**是确保满足项目及其干系人的信息需求的过程
- 作用：按沟通管理计划和干系人参与计划的要求优化信息传递流程
- 核心目标：在正确的时间，通过正确的渠道，将正确的内容传递给正确的受众
- 主要输入：资源管理计划、沟通管理计划、干系人参与计划、问题日志、项目沟通记录
- 工具与技术：**干系人参与度评估矩阵**、观察/交谈

### 13.8 监督风险
- **监督风险**是在整个项目期间监督风险应对计划实施、跟踪已识别风险、识别和分析新风险、评估风险管理有效性的过程
- 监督内容：风险应对是否有效；整体风险级别是否改变；已识别风险状态是否改变；是否出现新风险；风险管理方法是否依然适用；假设条件是否仍成立；应急储备是否需要修改
- 主要输入：风险管理计划、**风险登记册**、**风险报告**、工作绩效数据、工作绩效报告
- 工具与技术：
  - **技术绩效分析**：比较技术成果与计划
  - **储备分析**：比较剩余应急储备与剩余风险量
  - **风险审计**：评估风险管理过程的有效性（项目经理负责确保按频率开展）
  - **风险审查会**：定期安排，检查和记录风险应对的有效性

### 13.9 控制采购
- **控制采购**是管理采购关系、监督合同绩效、实施必要的变更和纠偏，以及关闭合同的过程
- 合同管理的法律性质：项目管理团队必须了解控制采购期间任何行动的法律后果
- 合同管理活动：收集数据和管理项目记录；完善采购计划和进度计划；建立采购数据收集分析和报告机制；监督采购环境；向卖方付款
- 重要原则：确保向卖方的付款与卖方实际已完成工作量之间有密切的关系
- 主要输入：需求管理计划、风险管理计划、采购管理计划、变更管理计划、进度基准、**协议**、采购文档、批准的变更请求
- 工具与技术：**索赔管理**（有争议的变更称为索赔，谈判是解决索赔和争议的首选方法）、绩效审查、挣值分析、趋势分析、检查、**审计**
- 主要输出：**采购关闭**（买方通过授权的采购管理员发出合同已完成的正式书面通知）、工作绩效信息

### 13.10 监督干系人参与
- **监督干系人参与**是监督项目干系人关系，通过修订参与策略和计划来引导干系人合理参与项目的过程
- 主要输入：资源管理计划、沟通管理计划、干系人参与计划、问题日志、干系人登记册
- 工具与技术：备选方案分析、根本原因分析、**干系人分析**、多标准决策分析、投票、**干系人参与度评估矩阵**、反馈、演示、积极倾听、文化意识、领导力、人际交往、政治意识

### 13.11 监控项目工作
- **监控项目工作**是跟踪、审查和报告整体项目进展，以实现项目管理计划中确定的绩效目标的过程
- 关注：比较实际绩效与计划；定期评估项目绩效；检查单个项目风险状态；维护准确且及时更新的信息库；为状态报告提供信息；做出预测；监督已批准变更的实施情况
- 重要输入：**工作绩效信息**（而非工作绩效数据！这是与其他控制过程的区别）
- 工具与技术：备选方案分析、成本效益分析、挣值分析、根本原因分析、趋势分析、偏差分析、投票
- 主要输出：**工作绩效报告**

#### 工作绩效数据、信息、报告的区别（必背！）
| 比较项 | 工作绩效数据 | 工作绩效信息 | 工作绩效报告 |
|--------|------------|------------|------------|
| 产生于 | 指导与管理项目工作过程 | 各控制过程（确认范围、控制范围等） | 监控项目工作过程 |
| 产生时间 | 随时产生 | 间隔一定时间 | 间隔较长，定期或特殊需要 |
| 主要用途 | 记录项目执行情况 | 反映执行与计划的偏差 | 综合对比，支持决策 |
| 回答的问题 | 是什么（what） | 为什么（why） | 如何解决和预防（how） |
| 使用者 | 项目团队 | 项目团队 | 团队、发起人、高管、客户 |

- 工作绩效报告的形式：仪表盘（RAG图、横道图、饼状图、控制图）、大型可见图表（BVC/信息发射源）、任务板（看板）、燃烧图（燃起图/燃尽图）

### 13.12 实施整体变更控制（必考！）
- **实施整体变更控制**是审查所有变更请求，批准变更，管理对可交付成果、项目文件、项目管理计划的变更，并对变更处理结果进行沟通的过程
- 项目经理对此承担**最终责任**
- 关键原则：
  - 在**基准确定之前**，变更无须正式受控
  - 一旦确定项目基准，必须通过实施整体变更控制过程处理变更请求
  - 所有变更请求**必须以书面形式记录**，纳入变更管理和/或配置管理系统
  - 每项记录在案的变更请求必须由一位责任人（通常是项目发起人或项目经理）批准、推迟或否决
  - 应由**CCB（变更控制委员会）**来开展实施整体变更控制过程
- 配置控制 vs 变更控制：
  - **配置控制**：重点关注可交付成果及各个过程的技术规范
  - **变更控制**：重点关注识别、记录、批准或否决对项目文件、可交付成果或基准的变更
- 配置管理活动：识别配置项、记录并报告配置项状态、进行配置项核实与审计
- 变更管理活动：识别变更、记录变更、做出变更决定、跟踪变更
- 主要输入：变更管理计划、配置管理计划、范围基准、进度基准、成本基准、需求跟踪矩阵、风险报告、工作绩效报告、**变更请求**
- 变更请求可能包含：纠正措施、预防措施、**缺陷补救**，以及文件或可交付成果的更新
- 影响项目基准的变更：应由CCB和客户或发起人审批
- 主要输出：**批准的变更请求**

## 记忆要点
1. **挣值公式口诀**：SV = EV - PV（进度偏差），CV = EV - AC（成本偏差），都是EV开头
2. **SPI/CPI判断**：大于1是好的（>1进度超前/成本节省），小于1是差的
3. **控制质量 vs 确认范围**：质量看"正确性"，范围看"验收"
4. **工作绩效三层次**：数据(what)→信息(why)→报告(how)
5. **控制资源关注实物资源**，不是人力资源
6. **变更控制三部曲**：书面记录→CCB评审→批准后实施
7. 监控项目工作的输入是**工作绩效信息**，其他控制过程的输入是**工作绩效数据**
8. **索赔管理**：谈判是解决所有索赔和争议的首选方法

## 常见题型
1. **选择题**：某项目PV=100万，EV=90万，AC=95万，则项目状态是？
   - 答：SV = 90-100 = -10（进度落后），CV = 90-95 = -5（成本超支）→ 进度落后且成本超支
2. **选择题**：以下哪个不是控制质量的数据表现技术？A.因果图 B.控制图 C.思维导图 D.散点图
   - 答：C（思维导图，教材明确排除）
3. **简答题**：简述整体变更控制的流程。
   - 答：①提出书面变更请求；②评估变更对项目的影响；③CCB审查批准/否决/推迟；④实施批准的变更；⑤跟踪验证变更效果；⑥更新项目文件和基准
4. **计算题**：已知BAC=100万，EV=40万，AC=45万，CPI=0.89。若按典型偏差，求EAC。
   - 答：EAC = BAC/CPI = 100/0.89 ≈ 112.36万
5. **选择题**：工作绩效报告产生于哪个过程？A.指导与管理项目工作 B.控制范围 C.监控项目工作 D.控制采购
   - 答：C
